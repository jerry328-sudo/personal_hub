# 归档、已读与滚动布局

- Agent API 支持 `start`（包含）、`end`（不包含）和 `time_field=updated|created|archived|completed`。筛选在数据库执行，时间规范化为 UTC，分页游标绑定全部条件。建议 Agent 先使用 `view=brief`，再按需读正文。
- 新迁移 `0004_archive_time.sql` 记录归档操作时间并为来源与归档时间建立索引。旧数据没有真实归档时间，以最新版本时间回填，不能恢复原操作时刻。
- 网页 Agent 的三种视图都排除归档，包括默认报告。归档集中按来源 Agent、归档日期、完成状态、阅读状态和标题/正文关键词筛选。每页只加载摘要，正文按需读取；前后翻页替换当前页，不无限积累 DOM。
- 各消息栏目与 Agent 页面支持一键已读。`POST /api/v1/admin/entries/read` 原子更新筛选范围内所有页的当前版本，仅管理员可用，要求同源。后续版本仍未读。共享数据库状态通过本页面事件、同源标签页通知及窗口重新聚焦同步。
- 导航里的全部信息和重要信息数字为准确未读数，归档为总数、待办为未完成数，均由数据库汇总。
- 归档消息的关联待办从网页的全部、未完成、已完成列表及侧栏计数中隐藏，取消归档后恢复显示，完成状态保持不变；独立待办不受影响。Agent API 保留这些待办供去重读取。过滤在数据库分页之前执行，网页同步其他标签页的归档变化。
- Agent 搜索栏与标题、消息列表使用同一限宽容器，在宽屏下保持左边缘对齐。
- 根页面固定为视口高度，Grid 行允许收缩；内容区独立滚动并阻断滚动向外传播。Agent 正文限宽，滚动容器占满主区域。

发布前执行 typecheck、lint、完整 API 测试和浏览器验证；先应用生产迁移，再部署 Worker。已有认证、域名和图标改动一并纳入 Git，保持仓库与已部署功能一致。

验证记录：67 项测试通过，包含 136 条跨页批量已读、重复操作幂等、新版本未读、归档时间边界、游标条件绑定和角色隔离。浏览器使用本地合成数据确认：35 个待办滚到底后根页面仍为 720px、scrollY=0；Agent 长正文只有最右侧主容器滚动；79 个归档每页只渲染 30 行，翻页后仍为 30 行；搜索能命中后续页；另一标签页的列表及正文同步已读。
