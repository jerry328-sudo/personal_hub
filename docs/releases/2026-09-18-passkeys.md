# 通行密钥登录

管理员可在“登录与安全”填写绑定名称、再次确认管理员登录密钥，按浏览器提示创建通行密钥。Windows 可选择 Windows Hello，Android 可选择系统支持的凭据管理器。登录页提供“通行密钥登录”，通过设备指纹、人脸或锁屏验证进入，无需再次输入管理员密钥。实际可用方式取决于设备和浏览器；保留管理员密钥作为备用入口。

普通退出只撤销会话，保留通行密钥。移除某个绑定会拒绝该凭据的后续登录，并立即使通过它建立的会话失效。在线修改管理员登录密钥会撤销所有现有会话及通行密钥绑定，未完成的绑定和登录验证也失效；用新密钥登录后重新绑定。Agent API 密钥不受影响。移除绑定不会主动删除 Windows / Android 凭据管理器中的本地记录。

## 模块与数据

- `src/server/modules/auth/passkeys.ts`：注册和登录选项、一次性挑战保存/消费、WebAuthn 校验、绑定列表与移除。使用 SimpleWebAuthn 的签名验证，ES256 / RS256；站点 RP ID 从可信的 `APP_ORIGIN` 取主机名，注册与登录都强制用户验证，使用可发现凭据。
- `src/server/modules/auth/service.ts` 的 `createAdminSession`：密钥登录与通行密钥登录共用 Session 签发逻辑。
- `src/server/modules/auth/repository.ts`：Session 带可选 `passkey_id`，在签发和读取时检查绑定仍有效；凭据版本防止修改密钥与登录并发。
- `migrations/0005_passkeys.sql`：`admin_passkeys` 只保存公钥及元数据；`webauthn_challenges` 保存五分钟挑战，绑定 HttpOnly / Secure / SameSite Cookie，注册还绑定管理员 Session。`DELETE RETURNING` 原子消费挑战，防止重放；过期记录在下一次发起时清理。管理员有固定随机 WebAuthn user ID。
- `src/web/passkeys.ts`：浏览器注册/认证 API 与中文取消、兼容性提示。
- `PasskeySettings`：新增和移除绑定（上限 20 个），展示创建时间、最近使用时间。私钥和管理员密钥均不写入网页存储。

## HTTP 接口

| 方法 | 路径 | 身份 |
|---|---|---|
| GET | `/api/v1/auth/passkeys` | 管理员 Session |
| POST | `/api/v1/auth/passkeys/register/options` | 管理员 Session，正文 `{name, secret}` 再次验证管理员密钥 |
| POST | `/api/v1/auth/passkeys/register/verify` | 同一个 Session + 挑战 Cookie，正文为 WebAuthn 注册响应 |
| POST | `/api/v1/auth/passkeys/login/options` | 未登录可用，返回可发现凭据登录参数，不暴露绑定清单 |
| POST | `/api/v1/auth/passkeys/login/verify` | 挑战 Cookie + WebAuthn 认证响应，成功签发 Session |
| DELETE | `/api/v1/auth/passkeys/:id` | 管理员 Session |

全部写接口要求同源 Origin；登录与管理员密钥验证复用登录限速。全部响应禁止缓存。切换正式域名会改变 RP ID，现有通行密钥无法直接迁移，需要用管理员密钥重新绑定。

## 发布与验证

先执行 `npm run db:migrate:production`，再执行 `npm run deploy:production`。迁移为新增表/列，保留原有消息、Agent 和管理员会话。无需新增 Cloudflare Secrets，也不需要 Cloudflare Access。

迁移前生产 D1 Time Travel 恢复点：`00000016-00000000-000050ea-81bb6ca04ead2a85792371518cf81437`。仅在确需恢复时使用，恢复会影响该点之后的写入。

新增 13 项 Workers 集成测试，以软件认证器生成真实 ES256 / RS256 签名，覆盖注册、登录、退出后重新登录、单独撤销及关联 Session 失效、密钥轮换、一次性挑战并发消费、过期、域名/RP/挑战篡改、错误签名、用户验证/在场标记及计数器。浏览器检查登录与管理页面、备用密钥登录和窄屏布局。真实 Windows Hello / Android 系统交互需由设备持有人完成；自动化浏览器不支持虚拟认证器。

参考：[SimpleWebAuthn 服务端](https://simplewebauthn.dev/docs/packages/server)、[浏览器端](https://simplewebauthn.dev/docs/packages/browser)。
