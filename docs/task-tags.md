# 待办标签

每条待办可以使用多个标签，例如同时标记“工作”和“论文”。标签独立于来源，可与来源、完成状态组合筛选。

## 网页与 MCP 面板

- 在“待办 → 管理标签”新增、重命名或删除标签。
- 新建待办时可多选标签，已有待办点击“标签”即可增删关联。
- 标签筛选包含全部标签、无标签和各个已有标签；本版一次按一个标签筛选。
- 删除标签只解除该标签与待办的关联，待办及其他标签保留；最后一个标签移除后归入“无标签”。
- 清除已完成待办同时遵循当前来源和标签筛选，覆盖所有分页。搜索文字不限制清除范围，确认框会显示实际范围。
- 已有待办初始为无标签，不自动按来源分配标签。

## 权限

| 操作 | 管理员 / 总管 | 普通 Agent | 只读 Agent |
| --- | --- | --- | --- |
| 读取标签目录 | 全部 | 全部 | 授权待办使用的标签 |
| 新增、重命名、删除标签 | 可以 | 不可以 | 不可以 |
| 给待办添加、移除已有标签 | 可管理范围 | 仅自己的待办 | 不可以 |

MCP 还要求对应的读取或写入授权；只读授权不能通过面板执行写操作。标签不会扩大原有待办访问权限。

## REST API

`{role}` 使用 `admin`、`manager`、`agent` 或 `reader`，沿用对应身份的现有鉴权。

| 请求 | 用途 |
| --- | --- |
| `GET /api/v1/{role}/task-tags` | 读取目录，支持 `limit` 和 `cursor` 分页 |
| `POST /api/v1/{role}/task-tags` | 新增标签，正文 `{"name":"工作"}`，仅 admin / manager |
| `PATCH /api/v1/{role}/task-tags/{id}` | 重命名，正文同上，仅 admin / manager |
| `DELETE /api/v1/{role}/task-tags/{id}` | 删除标签及关联，仅 admin / manager |

创建待办时传入 `tag_ids: ["tag_…"]`；更新待办时传入 `add_tag_ids` 和 / 或 `remove_tag_ids`。省略这些字段不改变已有标签，空数组也不会清空原关联。每个数组最多 100 个不同 ID，同一个 ID 不可在同次更新中同时添加和移除。

待办响应增加 `tags: [{id,name,created_at}]`，无标签时为 `[]`。标签名称做 Unicode NFKC 规范化并去掉首尾空格，长度 1–40，比较重名时忽略大小写；重名返回 409，添加已删除标签返回 404 或并发冲突 409。

待办列表和清除已完成接口新增 `tag_id`、`untagged=yes|no`。`untagged=yes` 仅选择无标签待办，`no` 不增加限制；`tag_id` 不可与 `untagged=yes` 同时使用。更改筛选后必须丢弃旧分页游标。清除结果的 `cleared` 仅计待办数量，不计级联删除的关联数量。

## MCP tools

- `list_task_tags`：读取目录。
- `create_task_tag`、`update_task_tag`、`delete_task_tag`：管理目录，仅管理员 / 总管且具有写入授权。
- `create_task`、`update_task`、`list_tasks`、`clear_completed_tasks`：使用与 REST API 相同的新增标签字段和筛选规则。

线上 `/api/docs` 和 `get_api_documentation` 同步提供规则。客户端若缓存工具清单，需要重新打开连接或刷新工具列表；已打开的旧面板需要关闭后重新打开。

## 数据迁移与验证

`0008_task_tags.sql` 仅新增标签表、关联表和索引，不改写原有待办。标签关联写入与待办写入使用同一事务，失败整体回滚；删除标签和待办通过外键清理对应关联。

集成测试覆盖角色权限、分页筛选、名称冲突、删除保留、清理计数和事务回滚。浏览器验收覆盖网页与面板的多选、增删改、筛选、普通 / 只读权限和手机布局。
